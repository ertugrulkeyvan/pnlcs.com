Docker-приложения

Клиенты устанавливают WordPress, n8n, базы данных или удалённые рабочие столы из каталога. Каждое приложение работает в Docker-контейнерах внутри хостинг-аккаунта клиента, в пределах памяти и CPU его тарифа. Нужен сервер Panelica.

Руководство по продаже Docker-приложений

Три способа продавать приложения

Их можно сочетать.

Хостинг с приложениями
Обычный тариф хостинга с лимитом контейнеров. Клиент получает сайт и в любой момент может добавить приложения на вкладке «Приложения».
Хостинг приложения
Заказ устанавливает одно приложение на домен клиента. Зафиксируйте приложение («Управляемый WordPress») или дайте клиенту выбрать его из каталога, чтобы один продукт покрывал все приложения.
Тариф для контейнеров
Ресурсы без сайта: без домена, а на странице услуги есть только вкладка «Приложения».

Все приложения аккаунта делят один лимит cgroup

Каждый контейнер, который запускает клиент, создаётся внутри cgroup-среза его аккаунта. Клиент с тарифом на 2 GB получает 2 GB на все свои приложения и не может использовать память другого клиента.

  • Никаких привилегированных контейнеров, дополнительных capabilities и монтирования путей хоста, даже для ключа биллинга
  • Тариф задаёт количество приложений, общий объём памяти и общий CPU
  • Клиент видит требования приложения к памяти до заказа
  • Если заказ не может установить приложение, он откатывается и никогда не остаётся собранным наполовину

Каталог формируете вы

Какие приложения существуют, решает сервер Panelica. Как их продавать, решает PNLCS: какие приложения вы предлагаете, какие выделяете, в каком порядке, с каким слоганом и логотипом.

  1. Подключите сервер PanelicaС API-ключом, у которого есть права на Docker.
  2. Выберите способ продажиПриложения в хостинге, хостинг приложения или тариф для контейнеров.
  3. Создайте продуктЗадайте лимит контейнеров, память и CPU, затем цену.
  4. Сформируйте каталогПредлагайте, выделяйте и упорядочивайте приложения; у 95 из 98 логотип есть сразу.
