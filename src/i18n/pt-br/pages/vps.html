VPS no Proxmox VE

Conecte um servidor Proxmox VE, instale imagens de nuvem oficiais pelo painel administrativo e venda produtos VPS. Quando a fatura é paga, o PNLCS clona, configura e inicia o servidor; o cliente o gerencia pelo portal do cliente.

ÁreaO que acontece

Ações destrutivas pedem confirmação

Qualquer ação que apague dados pede o nome do servidor. Tarefas longas, como uma reinstalação ou uma restauração, rodam em segundo plano e terminam mesmo se a página for fechada.

O que o PNLCS faz em cada evento de faturamento

EventoNo Proxmox
Pedido pagoClonado no pool com o próximo ID de VM, cloud-init aplicado, disco expandido, proteção ativada, iniciado
SuspensoInício automático no boot desativado e, em seguida, desligado, para que uma reinicialização do host não o traga de volta
ReativadoInício automático no boot ativado, iniciado
EncerradoParado, proteção removida, excluído junto com os discos; o endereço volta para o pool
UpgradeNovos núcleos e memória; o disco é expandido e nunca reduzido
A cada horaUso de disco e tráfego do mês, a partir das estatísticas do Proxmox

Máquinas que o PNLCS não criou ficam intactas

Um hypervisor normalmente roda mais do que servidores de clientes. Estas regras mantêm o PNLCS restrito ao que é dele.

  • Todo servidor que o PNLCS cria recebe uma tag e uma nota com o nome do serviço; ele só atua em máquinas com essa marcação
  • O token de API recomendado alcança apenas o próprio pool, e o teste de conexão avisa sobre permissões que o faturamento nunca usa
  • Os servidores são criados com proteção contra exclusão, removida apenas no momento do encerramento
  • Os clientes nunca veem o endereço do hypervisor
