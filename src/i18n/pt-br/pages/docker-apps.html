Apps Docker

Os clientes instalam WordPress, n8n, bancos de dados ou áreas de trabalho remotas a partir de um catálogo. Cada app roda como contêineres Docker dentro da conta de hospedagem do cliente, dentro da memória e da CPU do plano. Requer um servidor Panelica.

Guia para vender apps Docker

Três formas de vender apps

Elas podem ser combinadas.

Hospedagem com apps incluídos
Um plano de hospedagem normal com uma cota de contêineres. O cliente tem um site e pode adicionar apps pela aba Apps a qualquer momento.
Hospedagem de app
O pedido instala um app no domínio do cliente. Defina um app fixo (“WordPress gerenciado”) ou deixe o cliente escolher no seu catálogo, para que um único produto cubra todos os apps.
Plano de contêineres
Recursos sem site: sem domínio, e a página do serviço mostra apenas a aba Apps.

Os apps de cada conta compartilham um único limite de cgroup

Cada contêiner que um cliente inicia é criado dentro da fatia de cgroup da conta dele. Um cliente com plano de 2 GB tem 2 GB para todos os seus apps e não consegue usar a memória de outro cliente.

  • Nada de contêineres privilegiados, capabilities extras ou montagens de caminhos do host, nem mesmo para a chave de faturamento
  • Os planos definem o número de apps, a memória total e a CPU total
  • O cliente vê quanta memória um app exige antes de fazer o pedido
  • Um pedido que não consegue instalar o app é revertido, nunca fica pela metade

Você monta o catálogo

O servidor Panelica define quais apps existem. O PNLCS define como você os vende: quais apps oferecer, quais destacar, a ordem, o slogan e o logotipo.

  1. Conecte um servidor PanelicaCom uma chave de API que tenha os escopos do Docker.
  2. Escolha como venderIncluído, hospedagem de app ou plano de contêineres.
  3. Monte o produtoDefina a cota de contêineres, a memória e a CPU e, depois, o preço.
  4. Organize o catálogoOfereça, destaque e ordene os apps; 95 de 98 já vêm com logotipo.
