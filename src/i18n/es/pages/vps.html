VPS con Proxmox VE

Conecta un servidor Proxmox VE, instala imágenes cloud oficiales desde el panel de administración y vende productos VPS. Cuando se paga la factura, PNLCS clona, configura y arranca el servidor; el cliente lo gestiona desde el portal de clientes.

Las acciones destructivas piden confirmación

Todo lo que borra datos pide escribir el nombre del servidor. Las tareas largas, como una reinstalación o una restauración, se ejecutan en segundo plano y terminan aunque se cierre la página.

Qué hace PNLCS en cada evento de facturación

EventoEn Proxmox
Pedido pagadoSe clona en el pool con el siguiente ID de VM, se aplica cloud-init, se amplía el disco, se activa la protección y se arranca
SuspendidoSe desactiva el arranque automático y luego se apaga, para que un reinicio del host no lo vuelva a levantar
ReactivadoSe activa el arranque automático y se arranca
CanceladoSe detiene, se quita la protección y se elimina con sus discos; la dirección vuelve al pool
MejoradoNuevos núcleos y memoria; el disco crece y nunca se reduce
Cada horaUso de disco y tráfico del mes, a partir de las estadísticas de Proxmox

PNLCS no toca las máquinas que no ha creado

Un hipervisor suele ejecutar algo más que servidores de clientes. Estas reglas hacen que PNLCS se limite a las suyas.

  • Cada servidor que crea PNLCS lleva una etiqueta y una nota con el nombre de su servicio; solo actúa sobre las máquinas con esa marca
  • El token de API recomendado solo llega a su propio pool, y la prueba de conexión avisa de permisos que la facturación nunca necesita
  • Los servidores se crean con protección contra borrado, que solo se quita en el momento de la cancelación
  • Los clientes nunca ven la dirección del hipervisor
